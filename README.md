<h1 align="center">Plasticity Asset Tool</h1>

<p align="center">把常用模型变成组件，在 Plasticity 内浏览、保存与置入。</p>

组件库通过内嵌面板直接读取选中对象，默认保存与置入不占用系统剪贴板。点击缩略图后进入类似 **Ctrl+Shift+V** 的原生放置流程，在视口调整位置、大小和方向，再确认置入。

**当前验证环境：Windows x64 / Plasticity 26.1.3。** 自动安装仅开放这个版本；其他版本可被检测，但尚未开放自动安装。本项目是独立开源工具，安装时会修改 Plasticity 的入口并保留恢复备份。

## 功能一览

| 功能 | 可以做什么 |
| --- | --- |
| 📦 组件库 | 保存实体、曲线或混合选中对象；按库、文件夹、分类和标签组织，支持搜索与归档 |
| ↗ 原生置入 | 点击缩略图直接置入，使用 Plasticity 的原生定位、旋转、缩放与确认操作 |
| ◇ 几何预览 | 从模型数据生成正交缩略图与 3D 预览；支持实体和曲线，无需截图 |
| ± 布尔模式 | 实体组件可设置独立对象、合并、减去或相交；组组件支持按顺序执行不同布尔 |
| ⇄ 导入与导出 | 导入单个 `.patasset`；导出单组件、多选组件、分类或当前库 |
| ⚙ 控制中心 | 检查连接、切换目标窗口、安装与恢复插件，调整面板位置、导航和语言 |

## 下载与安装

1. 在 [Releases](https://github.com/mianxiu/plasticityAssetTool/releases) 下载 `PlasticityAssetTool-windows-x64.zip`，解压完整目录。
2. 双击 `PlasticityAssetTool.exe`，打开后台控制中心。发布包自带运行环境，无需另外安装 Python 或 Node.js；EXE 需要与发布目录一起使用。
3. 进入 **插件安装 → 检测安装**，选择 Plasticity 26.1.3。未找到时可输入安装目录重新检测。
4. 自行保存文档并关闭该版本的所有 Plasticity 窗口，点击 **安装插件**。核对目标与备份位置，确认 Windows 权限请求。
5. 安装完成后重新打开 Plasticity，按 **Tab** 打开组件库，再按一次关闭。

启动后台不会自动修改 Plasticity。安装、更新与恢复需要单独操作；已有插件可以在同一入口更新或恢复原始入口。完整状态与排错说明见 [插件安装文档](docs/wiki/Plugin-Installation.md)。

## 日常操作

### 保存与置入

在 Plasticity 中选中对象，完成当前建模操作，再打开组件库并点击 **保存组件**。插件会在保存时识别实体、曲线、混合对象，以及符合条件的原生组；仅打开面板不会读取组信息。

| 操作 | 效果 |
| --- | --- |
| **Tab** | 打开 / 关闭内嵌面板 |
| **点击缩略图** | 直接进入原生置入流程 |
| **缩略图上按住右键并拖动** | 临时旋转查看模型，松开恢复缩略图 |
| **点击「编辑」** | 打开可滚动侧栏，直接修改名称、分类、标签、备注和置入模式等信息 |
| **编辑预览中右键拖动 / 滚轮** | 旋转 / 缩放正交 3D 预览 |
| **视口内确认 / 取消** | 完成 / 取消当前置入，使用 Plasticity 原生操作 |

普通多选会保存为一个包含多个对象的组件。曲线和混合组件使用独立对象模式，不显示实体布尔设置。显式的「仅复制到剪贴板」仍可用于其他工作流，但不属于默认交换方式。

### 默认布尔模式

在实体组件的编辑侧栏直接切换四种模式。使用布尔模式前，先在 Plasticity 中选中目标实体，再置入组件。

| 模式 | 缩略图细外框 | 置入结果 |
| --- | --- | --- |
| 独立对象 | 中性灰 | 保留为独立对象 |
| 布尔合并 | 🟢 绿色 | 与选中的目标合并 |
| 布尔减去 | 🔴 红色 | 从选中的目标中减去组件 |
| 布尔相交 | 🔵 蓝色 | 保留目标与组件的相交部分 |
| 连续布尔组 | 🟣 紫色 | 按保存的子部件顺序逐项运算 |

没有有效目标时会拒绝布尔置入。**原位置粘贴始终使用独立对象模式。**

### 组组件与连续布尔

选中 **一个原生组**，点击保存组件：插件读取组名和直接子实体，按列表从上到下保存顺序，通过子部件名称前缀决定操作。

| 名称前缀 | 操作 |
| --- | --- |
| `+` | 合并 |
| `-` | 减去 |
| `&` | 相交 |
| `^` 或无前缀 | 独立对象 |

例如，下面的组件会先把外壳合并到选中目标，再减去内孔，标记块保持独立：

```text
连接件（组）
├─ + 外壳
├─ - 内孔
└─ ^ 标记块
```

置入时先整体定位并确认，再依次计算。计算期间显示步骤、部件名称与耗时，并暂时锁定当前窗口的操作；失败时回滚，成功后可整体撤销。

目前支持 **1–128 个直接子实体**，不支持嵌套组或组内曲线。普通多选不会按名称前缀执行连续布尔。按各步骤颜色显示几何预览仍在 [TODO](TODO.md) 中。

## 面板与后台

**优先展示组件。** 左侧导航可固定展开或鼠标悬停展开；组件卡片有 37 档大小，调整后自动保存。面板可固定显示，或以鼠标位置为中心打开；靠近窗口边缘时会自动调整位置。面板边框跟随 Plasticity 的 Accent Color。

**多窗口分别操作。** 每个内嵌面板绑定所在的 Plasticity 窗口；独立后台界面可以跟随最近激活的窗口，也可选择固定目标。

**后台由托盘控制。** 同一安装目录仅运行一个实例，重复启动会复用已有后台。关闭控制窗口不会退出后台；手动启动的后台也不会随 Plasticity 关闭。双击托盘图标打开控制中心，右键菜单可以暂停连接或退出。后台离线后，Tab 面板会明确提示未连接。

控制中心默认地址为 [`http://127.0.0.1:15150/?control=1`](http://127.0.0.1:15150/?control=1)，提供中文 / English 切换。

控制中心标题下方和托盘右键菜单顶部显示工具版本，统一来自 `backend/version.py`。`-dev` 表示开发版；控制中心显示当前运行后台返回的版本，旧后台未提供版本时显示“—”。

## 文件、导出与备份

| 文件 / 目录 | 用途 |
| --- | --- |
| `library/library.sqlite3` | 本地组件数据库；保存组件时写入这里 |
| `.patasset` | 单组件交换包，包含原始模型、编辑信息及可选图片 |
| `PlasticityAssetTool-components.zip` | 批量导出包，内部是多个独立 `.patasset` |
| `PlasticityAssetTool-windows-x64.zip` | 程序发布包，包含启动器、后台和运行环境 |
| `.runtime/` | 本机设置、缓存、日志和插件恢复备份 |

单组件可从编辑侧栏导出；批量导出支持多选、当前分类或当前库。**批量 ZIP 需要先解压，再逐个导入其中的 `.patasset`**，目前不直接导入外层 ZIP。

组件包不是完整数据库备份：导入时会创建新组件，并放入当前库和文件夹。要完整备份，请通过托盘退出后台后复制整个 `library/`；更新程序时同时保留 `library/` 和 `.runtime/`，避免丢失数据、设置及入口恢复备份。

详细字段、格式限制及恢复范围见 [文件格式](docs/wiki/File-Formats.md) 和 [导入、导出与备份](docs/wiki/Import-and-Export.md)。

## 常见问题

- **Tab 提示未连接：** 启动后台，检查托盘是否暂停连接。端口或插件入口变更后按安装文档更新插件。
- **当前建模操作尚未结束：** 先在视口确认或取消该操作，再保存或置入组件；工具不会替你结束建模操作。
- **曲线没有缩略图：** 已支持从原生曲线数据生成预览；首次生成需要连接 Plasticity 并加载匹配插件，失败不会删除已保存模型。
- **已安装，但缺少备份：** 找回原安装目录的 `.runtime/`。后台不会覆盖无法验证的入口；详见安装文档。
- **能导入 STEP / OBJ / 整个 Plasticity 文档吗：** 当前组件包导入不处理这些格式。先在 Plasticity 中打开模型，再选中对象保存为组件。原生模型跨版本兼容性尚未保证。

## 从源码运行

开发需要 **Windows、Python 3.10+ 和 Node.js/npm**。发布包用户无需执行这些命令。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start.ps1
```

`start.ps1` 构建前端并启动后台；后台已经运行时复用现有实例。调试代码修改后，通过托盘退出旧后台再启动。

| 目录 | 内容 |
| --- | --- |
| `backend/` | 组件数据库、模型通信、预览、托盘与服务 |
| `plasticity-asset-tool-app/` | Solid Web UI |
| `plasticity-javascript-payloads/` | 内嵌面板与 Plasticity 原生工作脚本 |
| `installer/` | 插件安装、更新与恢复 |
| `packaging/` | Windows 发布包构建 |
| `tests/` | 自动测试与发布验证 |
| `docs/` | 安装、文件格式与性能说明 |

运行 Python 测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

前端构建、发布包与性能资料分别见 [应用目录](plasticity-asset-tool-app/)、[发布构建脚本](packaging/build_release.py) 和 [Tab 性能说明](docs/tab-performance.md)。生成程序、本地模型库、运行缓存和安装备份不提交到仓库。

## UI 自动更新

源码运行时，修改前端后在 `plasticity-asset-tool-app/` 执行 `npm run build`。已加载此功能的后台页面和 Tab 内嵌面板约每 3 秒检查新构建，校验 HTML、脚本与样式完整后，自动重载组件库页面；不会刷新 Plasticity 主界面，也不会重复投递模型操作。

保存、置入、编辑、右键旋转预览、批量导出和后台安装期间会延迟更新。隐藏的 Tab 面板等下次展开并空闲时更新；分组、搜索、分类与排序会恢复。断连或操作结果不明时先保留旧页面，不以刷新清除错误。

首次安装本功能，需要先让已有组件库页面加载新版本一次：后台页面可重新加载；旧的常驻 Tab iframe 可在自行保存文档后正常重启 Plasticity。之后仅更新前端构建无需重启宿主或后台。入口补丁、原生接口和 Python 后台代码的变更不属于此 UI 更新功能；打包版仍须先替换实际使用的前端文件。

构建时保留旧的带哈希资源，让尚未结束编辑的旧页面仍能加载所需模块；需要清理旧资源时，先退出使用这些页面的后台，再清理 `dist/` 并重新构建。

开发服务器的 `npm run dev` 使用 Vite 自带 HMR，生产构建使用上述安全更新流程。
